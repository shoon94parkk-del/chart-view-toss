# 사용자 흐름 추가 개선 — 0.9.8

기존 전체 감사의 12개 수정 이후, 검색 → 종목 선택 → 비교 → 이전 화면 복귀의 반복 조작을 점검했다. 기존 DART 계산·저장 질문·관심종목·PICK 의미를 유지한다.

| 불편/재현 조건 | 개선 후 동작 |
| --- | --- |
| 검색어를 바꿀 때 직접 전체 삭제해야 함 | 검색창 안의 44px 지우기 버튼으로 관심종목 목록 복귀 |
| 검색 실패 후 입력을 바꿔야 재조회됨 | 검색어를 유지하는 재시도 버튼, 실패와 검색 결과 없음 구분 |
| Escape로 종목 창을 닫을 수 없음 | 닫기·취소·Escape·기존 네이티브 뒤로가기를 같은 종료 처리로 연결 |
| Tab이 창 뒤 메뉴로 이동하고 종료 후 초점이 사라짐 | 배경 inert, 창 안 Tab 순환, 종료 시 호출 버튼 초점 복원 |
| 목록 아래 종목 선택 시 스크롤/초점 초기화 | 선택 후 같은 결과 위치·초점 유지, 선택 상태 aria-pressed |
| 새 선택 칩이 가로 목록 밖에 숨고 삭제 대상/터치 영역이 불명확 | 새 칩 자동 노출, 종목명 포함 해제 레이블, 44px 터치 영역, 검색 글자 16px |
| 홈 시장 응답에 일부 지표만 있으면 계속 불러오는 중으로 표시됨 | 완료 후 자료 없음 표시, 주요/보조 지표 독립 재시도, 빈 캐시 우회. 기존 관측값과 기준시각 유지. 주 시장 갱신이 보조 지표를 지우지 않음 |
| 브라우저 뒤로 → 앞으로 → 앱 뒤로 시 홈으로 잘못 이동 | 현재 방문의 이동 위치를 history.state에서 복원. 직접 진입/새로고침의 루트 종료 의미 유지 |

## 원인과 검증

- 종목 선택은 목록 전체를 다시 그리며 스크롤과 활성 요소를 잃었다. 상태를 캡처하여 복원한다. 검색 상태도 다시 그리기와 함께 유지하므로 관심종목을 눌러도 진행 중 표시가 사라지지 않는다.
- 시장 카드는 행 누락을 무조건 로딩으로 해석했다. 실제 요청 pending과 완료 후 결측을 분리한다. 사용자가 누른 재시도는 클라이언트의 빈 응답 캐시를 우회한다.
- 이전 이동 수를 popstate마다 감소시켜 앞으로 이동도 뒤로로 계산했다. 방문 식별자와 이동 위치를 pushState에 저장하고 복원한다. URL과 기존 루트 엔트리는 덮어쓰지 않는다.
- `tests/selection_usability_qa.mjs`에서 Escape 실패 및 앞으로 이동 후 잘못된 홈 복귀를 먼저 재현했다. 320/390/430px에서 수정 후 검색 재시도/초기화, 초점 격리/복귀, 선택 스크롤 유지, 부분 시장 데이터 종료/재시도, 보조 지표 유지, 이전 화면 복귀, 가로 넘침과 JS 오류를 확인한다.
- 기존 경험 감사·로딩/공유·모바일 회귀와 `npm run build`를 함께 실행한다. 스크린샷: `output/playwright/selection-usability/`.

## 배포 범위

기존 GitHub/Render 웹사이트만 0.9.8로 갱신한다. 백엔드 스키마/추가 유료 API는 필요하지 않다. 웹 Chromium의 모바일 폭 및 키보드 검증이며 실제 Android/iOS Apps in Toss 검증을 대신하지 않는다.
