# 실행 계획

1. 공식 연구 자료와 기준 SHA를 고정한다. 연구 담당자는 원본·날짜·단위·ETF 통화를 검증하고 저장소를 편집하지 않는다.
2. 공유 데이터 담당자는 실패하는 수치·현금 분류·순유입·중복 계산·자료 감지 검사를 먼저 작성한다. 기존 게시 계약을 유지하면서 모형2와 증거를 구현한다. 부모가 최종 수집·통합·게시를 직렬화한다.
3. 부모는 JS 계산·게시 검증 회귀를 먼저 추가하고 Python과 같은 현금 산식을 구현한다. UI 담당자는 분류·가정·시나리오·접근성 브라우저 회귀를 먼저 추가하고 해당 화면만 편집한다. 기존 v1 fixture는 유지한다.
4. 출처 연구 담당자가 실제 diff·수치·가정 문구를 독립 재검토한다. 관련 Python 검사, 전체 Node/build/E2E, 모바일 연속성, SDK 빌드를 수행한다. 공용 QA 출력은 하나씩 실행한다.
5. 두 저장소의 정확한 검사 commit을 PR/CI로 통합한다. 기존 Render 브랜치 승격 후 실제 배포 화면의 원격 JSON→JS 계산→표시값과 상세 버전을 대조한다. 자료 자동 수집 workflow도 실제 실행하고 게시된 결과를 확인한다. 실제 Toss 기기 출시는 별도 검증이다.

검토 집중: 헤지 비용과 FX의 중복, 운용수익의 순유입 재합산, 배당의 중복, NAV 미확인과 실제0의 혼동, 가정 변경 시 현금 산식 재계산, 메인과 시나리오 분리, 같은 버전의 경고 갱신, 기존 SDK 호환.
