# PCE and publication clarity implementation plan

> **For agentic workers:** Execute the bounded backend/frontend tasks with disjoint ownership, then perform an independent integrated review.

**Goal:** Add official PCE/core PCE histories beside CPI/PPI, distinguish observation month from release date, and display honest expected-versus-actual availability.

**Architecture:** Extend the existing optional saved inflation cache and its lazy view. The original sixteen macro rows and Home/PICK/LAB remain unchanged. Fetch BEA data only in the scheduled collector; no provider requests on the app request path.

**Tech Stack:** Existing Python requests/stdlib XML, Vite vanilla JS, Node24, Playwright Chromium/WebKit.

**Spec:** User's October16 request for PCE alongside CPI/PPI and forecast/actual traffic lights. Existing project guardrails and release authorization apply.

## Global constraints

- PICK/LAB selection, scores, records, formulas, API/display conditions and disclaimers are unchanged.
- PCE YoY and MoM both use SA indexes; CPI/PPI retain NSA YoY and SA MoM.
- Unknown forecast values/publication times stay unknown. No retrospective forecast receipt is fabricated.
- Use existing CI/promotion/Render services; native Toss Sandbox remains a separate gate.

## Review focus

- Provider stale-but-HTTP200 data must not claim freshness after a newer verified publication.
- Date-only publications must not become guessed midnight or08:30 timestamps.
- A current revised observation must not be labeled a first-release actual.
- A missing/after-release forecast must remain gray for the matching month/rate/basis.
- Existing four-series backends must leave all sixteen legacy indicators usable.
