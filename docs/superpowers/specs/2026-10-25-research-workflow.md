# 저장한 분석을 다시 확인하는 흐름

사용자는 2026-10-25 기능 검토 후 제안한 순서대로 개선 진행을 승인했다. 이번 범위는 뉴스 더 보기, 날짜별 재점검, 이름 붙인 검색/비교 세트, 뉴스 근거 스크랩이다. 기준 main: `bacb74b4796e1934d844288180b1c43813564a24`.

## 사용자 동작

1. 관심 뉴스에서 현재 필터에 맞는 이미 받은 기사를 12개씩 더 본다. 종목 상세에 다녀와도 같은 방문의 표시 수를 유지한다. 필터/정렬 변경은 처음 12개로 돌아간다. 요약 요청과 추가 기사 조회는 더 보기만으로 발생하지 않는다.
2. 기존 '다시 확인할 내용'에서 기한 지남/오늘/예정/완료를 구분한다. 한국 날짜 기준으로 분류하고 확인 완료, 날짜 미루기, 완료 취소를 제공한다. 홈은 기존 작은 영역을 유지한다. 완료는 사용자가 확인했다는 기록이며 최신 공시를 자동 검증했다는 의미가 아니다. 새로운 저장 질문/공시 변경은 이전 완료 표시로 가리지 않는다.
3. 검색 조건과 비교 종목/기간에 이름을 붙여 각각 최대 5개 저장, 실행, 이름 변경, 삭제한다. 기존 검색 필터/기간 처리와 6종목 비교 제한을 재사용한다. 적용은 현재 데이터를 조회하며 저장 당시 결과나 수익률로 가장하지 않는다. 비교 세트를 불러와도 관심종목을 자동 변경하지 않는다.
4. 뉴스에서 관련 종목을 선택하고 원문 제목/URL/출처/발행일/저장일/개인 메모를 '조사 근거'로 저장한다. 본문을 복제하거나 기존 DART 질문을 덮어쓰지 않는다. 종목 상세에 저장 근거와 원문 열기/메모 수정/삭제를 제공하고 관심 화면에서 다시 찾아갈 수 있게 한다. 미국 종목도 근거 저장은 지원한다. 같은 종목/URL 저장은 중복되지 않는다.

## 구현 선택

기존 화면 안에 작은 행과 접기 영역을 추가하는 방식을 채택한다. 별도 대형 홈 카드/새 하단 탭/새 서버는 만들지 않는다. 검토에서 제안한 푸시, 계정 동기화, 기준지수 비교, 통합 일정, 재무 추세, 백업은 후속 범위다.

- Vanilla Vite, Apps in Toss SDK 3.5.0, 기존 저장 API/네이티브 내비게이션을 유지한다.
- 새 데이터는 기기·토스 익명 계정별 저장에 포함하고 초기화한다. 공유 URL/분석 이벤트에 개인 메모·세트 이름·기사 저장 기록을 넣지 않는다.
- 기존 자료는 읽기만으로 이관/수정하지 않는다. 손상 저장은 오류를 알리고 덮어쓰지 않는다.
- 저장 성공 전 성공 UI를 표시하지 않는다. 중복 클릭, 실패 후 재시도, 계정 전환/초기화 이후 늦은 저장을 보호한다.
- 새 UI는 320px/Android/iPhone WebKit에서 overflow 없이 읽고 누를 수 있어야 한다. 독립 조작은 44px 이상, 키보드 초점과 펼침을 보존한다.
- 뉴스 저장은 HTTPS 원문만 허용하고 URL 자격증명/위험 프로토콜/HTML 삽입을 거절한다. 개인 메모는 300자, 종목당 근거 20개/전체 100개로 제한하며 한도 초과를 조용히 삭제하지 않는다.
- PICK/LAB 선정, 산식, 성과, 출처/날짜, 시세 최신성, API/캐시/수집/배포 경로는 그대로 둔다.

## 완료 근거

각 데이터 동작의 실패→통과 Node 회귀, 실제 화면의 저장/복귀/초기화/부분 실패 검증, 기존 `qa:prepush` 전체, 관련 모바일 QA, AIT 빌드 및 독립 검토를 수행한다. 실기기 Toss/운영 게시 여부는 별도로 기록한다.
