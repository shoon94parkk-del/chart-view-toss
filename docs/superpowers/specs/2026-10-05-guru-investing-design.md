# 거장 투자법 — 버핏·린치 원칙 기반 재무 조건 조회

작성: 2026-10-05. 상태: 사용자 설계 승인 완료, 구현 계획 검토 대기. 제품 코드·데이터 수집 작업·배포는 아직 변경하지 않았다.

## 목적과 승인된 방향

사용자는 주식 인사이트를 얻고, 기업을 찾아낸 근거를 이해하며, 추가로 확인할 질문을 만들 수 있어야 한다. 사용자가 승인한 방향은 기존 기술적 스크리닝과 구분한 **분석 → 거장 투자법**, 버핏·린치 선택, 조건에 맞는 기업과 선정 근거, 펼쳐보는 기준 설명, 기존 종목 상세 연결이다.

모바일의 작은 글자·짧은 행·적은 여백을 유지한다. 하단 주 메뉴는 늘리지 않는다. 큰 인물 사진, 소개 배너, 수익률 순위, 개인화된 매수·매도 판단은 이 기능에 넣지 않는다. 이번 문서는 새로운 재무 수집과 결과 형식을 포함하는 구체적 설계이며, 앞서 승인된 화면 아이디어의 기술적 범위를 명확히 한다.

## 확인한 현재 구조

- Toss 클라이언트: `src/main.js`의 분석 메뉴, `src/routes.js`, `src/uiIdentity.js`, 지연 로드 화면과 공용 요청 클라이언트가 있다.
- 기술적 조건 검색은 `src/analysisViews.js`와 `/static/data/screener.json`을 사용한다. 기존 필터·지표·조회 계약은 그대로 보존한다.
- 공유 백엔드: `dart_financial_service.py`가 DART 공시에서 순이익·영업현금흐름·자산·부채·자본 등의 최근 3개 연도 자료를 추출한다. 확인한 체크아웃의 사전 수집 대상은 **14개 기업**이다.
- `scripts/generate_valuation_cache.py`는 **67개 종목** 중심이다. 이를 전체 시장 재무 스크리너로 취급하지 않는다.
- 기존 GitHub Actions에 서버 측 `DART_API_KEY`와 재무 캐시 생성 경로가 있다. 브라우저에 인증키를 전달하지 않는다.
- 2026-10-02 운영 스크리너 확인에서는 전체 대상 2,652개 중 동일 거래일 자료가 있는 2,505개였다. 이는 그 시점의 관측이며 새 기능의 고정 개수나 수집 성공 보장이 아니다.

## 화면과 동선

1. 분석 메뉴의 ‘종목 찾기’ 그룹에서 기존 조건 검색 다음에 ‘거장 투자법’을 배치한다. 설명은 ‘버핏·린치 원칙으로 재무 조건 확인’이다.
2. 새 경로는 `#gurus`, `#gurus/buffett`, `#gurus/lynch`; 기본 선택은 버핏이다. `/gurus` 고정 직접 진입 경로와 기존 Toss 딥링크 방식도 지원한다. 뒤로 가기·새로고침·종목 상세 복귀 시 선택 전략, 검색, 펼친 기업, 스크롤을 복원한다.
3. 상단은 화면명, 두 개의 작은 선택 버튼, 선택 전략의 한 줄 설명, 기준일/확인 범위로 구성한다. 원칙 소개와 계산 설명은 접힌 ‘선정 기준’에 넣는다.
4. 검색은 종목명·코드, 시장 필터는 전체/KOSPI/KOSDAQ이다. 이미 선정된 결과 안에서 검색한다는 문구를 표시한다. 기본 정렬은 이름순이며 우열 점수나 ‘최고 추천’ 순위를 만들지 않는다.
5. 기업 행에는 이름·시장, 전략별 핵심 수치 2개와 짧은 근거를 표시한다. 버핏은 평균 ROE·부채비율, 린치는 EPS 성장률·과거 실적 기준 PEG를 우선한다. 숫자만으로 결론을 설명하지 않는다.
6. ‘선정 근거’ 버튼을 누르면 연도별 수치, 조건별 충족값·기준, 보고서 원문, 추가 확인 질문을 펼친다. 별도 ‘종목 상세’ 버튼은 기존 가격·차트·재무 상세를 연다. 행 전체에 여러 겹의 클릭 동작을 만들지 않는다.
7. 상세에서 기존 기술적 조건 검색으로 이동할 수 있다. 재무 조건과 기술 지표의 기준일을 각각 표시하며, 기술 조건 검색으로 이동했다고 재무 선정 조건이 유지된 것처럼 표시하지 않는다.

### 모바일 확인 기준

- 320/390/430px에서 가로 넘침 없이 핵심 수치와 출처 날짜를 읽을 수 있어야 한다.
- 일반 글자는 기존 밀도와 같은 13~14px, 보조 정보는 12px, 일반 조작 영역은 44px 이상을 기준으로 한다. 결과 기본 행은 72~88px를 목표로 하되 접근성 글자 확대에서는 자연스럽게 늘어난다.
- 390×844px에서 데이터가 있다면 첫 결과가 상단에서 320px 이내에 시작하고, 소개 때문에 결과가 밀려나지 않아야 한다.
- 선택 상태는 색상뿐 아니라 글자·선택 속성으로 구분한다. 출처·연도·단위는 말줄임으로 숨기지 않는다. 기존 색상과 안전 영역·네이티브 뒤로 가기 계약을 재사용한다.

## 투자 원칙과 실제 필터의 구분

버핏의 원칙은 지속적인 이익, 높은 자본수익성, 낮은 차입 부담 등을 참고한다. 린치의 원칙은 성장과 가격을 함께 살펴보는 관점을 참고한다. 아래 수치와 관측 기간은 **차트뷰가 정한 한국시장용 조회 기준**이다. 원저자가 그대로 지정한 공식 필터나 해당 투자자가 추천한 종목으로 소개하지 않는다.

### 공통 데이터 조건

- 현재 스크리너 원집합의 KOSPI/KOSDAQ 기업을 수집 대상으로 삼는다. 새 작업은 14개 기업에만 제한하지 않고 종목코드→DART 고유번호를 연결해 확장한다.
- 금융업·리츠·SPAC·우선주는 일반기업 비교 조건에서 제외한다. 기존 기업/시장 분류의 확인 가능한 근거를 사용하고, 필요한 분류가 불명확한 경우 검증 부족으로 집계한다. 이름에 포함된 단어만으로 일반기업임을 확정하지 않는다.
- 연간 연결재무제표(CFS)를 우선하며, 연결이 없는 기업은 같은 기간 전체에 일관된 별도재무제표(OFS)를 사용할 수 있다. 연도 사이에 기준이나 통화가 다르면 통과시키지 않는다.
- 모든 원자료는 연도·계정·통화·보고서 접수번호·공시일과 연결한다. 최신 확인된 정정 공시의 비교 수치를 우선하고, 기존 값이 정정되면 의존 지표와 결과를 다시 계산한다.
- 결산 기간이 비교 가능하고 필요한 연도가 연속이어야 한다. 0/음수 분모, 누락, 중복된 계정, 통화 혼합, 불명확한 EPS 종류는 미검증으로 처리한다. 누락을 0으로 바꾸지 않는다.

### 버핏 · 우량기업 원칙 참고

‘최근 3개 연도의 수익성과 현금흐름, 부채 부담을 확인해요.’

| 조건 | 차트뷰 v1 기준 |
|---|---|
| 이익 지속 | 최근 3개 연도 순이익이 각각 양수 |
| 자본수익성 | 각 연도 ROE ≥10%, 3년 산술평균 ROE ≥15% |
| 현금 뒷받침 | 3년 영업현금흐름이 각각 양수이고, 3년 합계가 같은 기간 순이익 합계 이상 |
| 부채 부담 | 최근 연도 부채총계/자본총계 ×100 ≤100% |

ROE는 같은 기준의 총순이익 ÷ 해당 연도 평균 총자본 ×100으로 계산한다. 3년 ROE에는 시작 연도 전년 말까지 **4개 연도 자본**이 필요하다. 이를 ‘공시 총자본 기준 ROE’로 명시하며 공급자의 최신 단일 ROE로 대체하지 않는다. 시작/끝 자본 모두 양수여야 한다.

부채총계 기준 부채비율은 이자 발생 차입금 비율과 다르다. 화면에서 이를 ‘차입금이 거의 없다’로 바꾸어 설명하지 않는다. 현금흐름은 영업현금흐름이며 잉여현금흐름·버핏의 오너이익과 동일하다고 부르지 않는다. 경제적 해자·경영진·적정 매수가격은 이 조건만으로 검증되지 않는다.

추가 질문: ‘높은 수익성의 이유가 일시적 요인인가?’, ‘유지·성장 투자에 필요한 현금은 얼마인가?’, ‘현재 가격에도 이 기업을 보유할 근거가 있는가?’

### 린치 · 성장과 가격 원칙 참고

‘과거 주당이익 성장과 최근 연간 실적 대비 가격을 함께 확인해요.’

| 조건 | 차트뷰 v1 기준 |
|---|---|
| 비교 가능한 주당이익 | 연속 4개 연도의 보통주 기본 EPS가 각각 양수 |
| 성장 | 3년 EPS CAGR 10~30%, 최근 연도 EPS가 전년보다 증가 |
| 성장 대비 가격 | 최근 연간 EPS 기준 PER ÷ EPS CAGR(퍼센트 숫자) ≤1.0, PER >0 |
| 재무 확인 | 최근 연도 부채총계/자본총계 ≤100%, 최근 연도 영업현금흐름 >0 |

EPS CAGR = ((마지막 EPS/3년 전 EPS)^(1/3)−1)×100. 성장률 20%를 PEG 분모에 20으로 넣으며 0.2를 넣지 않는다. 가격은 스크리너의 동일 거래일 원화 종가, EPS는 확인된 최근 연간 원화 보통주 기본 EPS를 사용한다. **‘연간 실적 기준 PER’·‘과거 3년 성장 기준 PEG’**라고 명시한다. TTM PER, 예상 PER, 미래 성장 전망과 구분한다.

EPS 계정 식별을 추가하되 순이익을 현재 발행주식 수로 나누어 과거 EPS를 만들어내지 않는다. 주식분할·병합·주식배당 등으로 과거 EPS와 현재 주가의 주당 기준이 달라지는 경우, 정정 비교 수치 또는 확인된 기업행동 조정을 통해 같은 기준임을 검증해야 한다. 조정 범위·종류가 불확실하면 린치 통과 대상에서 제외한다. 희석 EPS나 우선주 EPS로 조용히 대체하지 않는다.

추가 질문: ‘최근 성장이 본업에서 발생했나?’, ‘향후에도 이익이 늘 근거가 있나?’, ‘재고·매출채권은 매출보다 빠르게 늘고 있나?’

## 데이터 수집과 결과 계약

- 기존 DART 계정 선택·통화·접수번호 검증 도구를 재사용하되, 기존 `/api/financial-history` 응답은 변경하지 않는다. 거장 조회용 연간 4년 이력과 EPS·기업행동 검증은 별도 캐시에 보관한다.
- 수집은 GitHub Actions에서 실행한다. 전 종목을 방문 시 조회하거나 기존 상세 API를 전 종목에 강제 호출하지 않는다. 호출 예산·동시 요청 상한·타임아웃·재시도 상한을 두고 중단 지점을 저장한다.
- 현재/직전 보고서가 이미 확인된 기업은 저장 이력을 재사용한다. 신규 공시·정정·기업행동·원집합 변경을 우선 갱신한다. 초기 구축은 여러 실행에 걸쳐 이어갈 수 있게 하고 기존 DART 작업과 호출 예산을 조정한다. 요청 제한(020)에서는 즉시 추가 요청을 중단한다.
- 최신 공시 확인은 일 단위의 제한된 작업으로, 필요한 과거 보고서는 점진적으로 채운다. 가격과 린치 결과 계산은 스크리너의 새 거래일 자료가 검증된 뒤 갱신한다. 저장된 각 재무 수치의 사업연도는 가격 기준일과 별도 표시한다.
- 출력은 신규 `/static/data/guru_screening.json`: `schemaVersion`, `criteriaVersion`, `generatedAt`, `tradeDate`, `financialAsOf`, 출처, 전략별 결과·집계·갱신 상태. 통과 기업에는 종목 식별자·시장·기준일·핵심 지표·실제 충족값과 근거 식별자를 넣는다.
- 전략마다 `universeCount`, `unsupportedCount`, `pendingCount`, `insufficientCount`, `evaluatedCount`, `matchedCount`를 저장한다. 집계는 원집합 내 중복 없는 회사/종목 단위로 맞추고, evaluated는 pass+fail이다. 데이터 부족·수집 대기·지원 제외를 조건 미충족으로 섞지 않는다.
- 근거를 펼칠 때 새 읽기 전용 `/api/guru-investing/{ticker}`로 저장된 연간 수치·계정 출처·조건별 판단을 읽는다. 이 API는 저장 데이터만 반환하며 외부 공급자 수집을 시작하지 않는다. 결과 스냅샷 버전을 함께 요청해, 다른 버전의 근거를 같은 선정 근거로 표시하지 않는다.
- Yahoo는 기존 가격 수집과 필요한 기업행동 검증을 보완한다. 현재 67개 가치평가 캐시의 EPS/예상 EPS를 전 종목의 근거로 사용하지 않는다. 새 네이버 HTML 재무 스크래핑에 핵심 계산을 의존시키지 않는다.
- 검증 후 파일을 원자적으로 교체한다. 부분 수집 실패 시 마지막 검증값을 유지하되 실제 자료 시점·갱신 실패를 표시한다. 실패한 작업이 캐시를 빈 목록으로 덮어쓰지 않는다. 원집합에서 제외된 종목은 이전 통과 목록에 계속 남겨두지 않는다.

## 실패·빈 결과·범위 표시

- ‘조건 충족 0개’, ‘검증 가능한 재무자료 0개’, ‘수집 진행 중’, ‘요청 실패’를 별도 상태로 표시한다. 조건이 없다는 이유로 자동 완화하거나 예시 기업을 실제 결과에 섞지 않는다.
- 초기 수집 도중 화면은 실제 검증된 범위만 보여주며 ‘전체 대상 N / 검증 M / 수집 대기 P’를 명시한다. 14개 기업만 확인한 상태를 전 시장 조회 완료라고 소개하지 않는다.
- 결과 요청 실패 시 기존 유효 화면을 유지하고 재시도를 제공한다. 근거만 실패하면 기본 기업 행을 유지하고 해당 영역에서 재시도한다. 전략 전환 후 늦게 온 응답은 현재 선택을 덮어쓰지 않는다.
- 기준 거래일과 재무 공시 기준일이 확인되지 않은 결과는 통과 목록으로 게시하지 않는다. 최신 목표 보고서 수집 여부와 검사 시점을 표시해 오래된 재무자료를 현재 검증 완료로 설명하지 않는다.

## 구현 단위와 검증 범위

공유 백엔드는 별도 수집기·순수 조건 판정기·저장 근거 조회와 새 스케줄을 추가한다. Toss는 새 API 함수, `guruInvestingView.js`/CSS, 경로·메뉴·화면 식별·직접 진입 빌드를 추가한다. 기존 기술 스크리너와 공유 웹 UI를 다시 설계하지 않는다.

계산 검증은 경계값, 음수/0, 평균자본, 4개 연도 연속성, 혼합 재무 기준, 정정 공시, EPS 종류·소수·기업행동, CAGR/PEG 단위, 전략별 미검증 집계, 오래된 스냅샷·원집합 변경을 포함한다. 실공시가 있는 서로 다른 기업의 통과/미충족 사례를 원문과 대조한다. 실제 결과에 테스트용 기업을 섞지 않는다.

화면 검증은 두 전략 전환, 접힘 근거, 원문 열기, 검색·시장 필터, 모든 빈/실패 상태, 느린 응답, 상세 진입/복귀, 직접 주소와 재로딩, 모바일 320/390/430px, 기존 홈·스크리너·재무 상세 회귀를 포함한다. `npm test`, `npm run build`, 관련 Python 테스트와 백엔드 번들 검사를 수행한다.

배포는 공유 데이터/근거 API를 먼저 검증한 후 Toss 화면을 배포한다. 정확한 배포 커밋·백엔드 `/health`·운영 스냅샷·실제 모바일 브라우저 동선을 확인한다. 초기 수집 범위와 린치 EPS 검증 범위를 결과와 함께 보고한다. Render 웹 미리보기와 실제 Android/iOS Toss 공개 출시 완료는 구분한다.

## 참고한 원칙과 API 근거

- 버핏: [Berkshire Hathaway 1982 주주서한](https://www.berkshirehathaway.com/letters/1982.html)의 지속적 이익과 자본수익성·차입 부담에 관한 인수 원칙. 이 문서의 3년/10%/15%/100% 기준은 차트뷰 제안이다.
- 린치 참고 GARP: [Fidelity 전략 설명](https://research2.fidelity.com/fidelity/screeners/commonstock/strategy.asp?simpleStrategy=%7BF61E8D5C-32C9-499B-8F6D-DD6DAF53EB78%7D)은 성장과 가치평가를 함께 다룬다. 본 기능은 예상 성장 대신 확인 가능한 과거 EPS를 사용하는 차트뷰 변형이다.
- DART: [단일회사 전체 재무제표 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는 연간/분기 보고서, 연결/별도, 계정·통화·접수번호를 제공한다. 요청 제한은 키별 설정에 따르며 일반적인 제한 안내를 고정된 보장으로 해석하지 않는다.
