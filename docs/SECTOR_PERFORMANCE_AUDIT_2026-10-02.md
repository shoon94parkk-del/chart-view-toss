# Chartview Toss 섹터 히트맵·로딩·사용 흐름 점검

## 구현 범위

- 기존 종목 히트맵 아래 한국장/미국장 섹터 히트맵 추가. 섹터 선택 → 구성 종목 → 상세 분석으로 연결한다.
- 홈 첫 화면에서는 섹터 API와 추가 모듈을 요청하지 않는다. 해당 영역에 가까워질 때 로드하며 전체 히트맵에서는 이미 받은 자료를 재사용한다.
- 미국 11개 섹터의 대표 종목을 먼저 수집하고 받은 시세부터 표시한다. 전체 수집이 끝날 때까지 빈 화면으로 기다리지 않는다.
- 요청 범위는 한국 20개·미국 40개로 유지한다. 동일 요청 공유, 서버 캐시, 백그라운드 수집, 실패 후 재시도 간격을 적용한다.
- 섹터 색은 **수집 종목의 시가총액 가중 일간 등락률**이다. 공식 섹터 지수나 전체 시장 수익률이 아니다. 기준 거래일·집계 종목 수·시총 비중·제외 건수를 표시한다. 기존 회사 상세의 주간 업종 흐름은 별도 지표로 유지한다.
- 누락 시총, 미분류, 오래된 시세, 다른 거래일의 행은 제외한다. 한국은 KRX 업종·주요제품, 미국은 기존 산업 분류를 사용한다.

## 함께 수정한 불편

| 발견한 문제 | 적용한 수정 |

| 홈 지수 클릭이 비교 차트로 이동 | 선택한 지수의 실제 관측 포인트 차트로 이동; 기존 비교 종목 선택 보존 |
| 최신 홈 지수보다 이전 상세 값이 먼저 표시 | 관측시각을 비교하는 공통 저장소를 거쳐 표시; 과거 캐시의 역행 방지 |
| 빈 시세 응답에서 오류가 발생해 로딩이 남음 | 확인 불가와 재시도 표시; 빈 200·503·시간 초과·복구 검증 |
| 공시를 기다리는 동안 저장한 투자 조건도 사라짐 | 저장값·비교회사 즉시 표시, 현재 확인 진행 상태를 별도로 표시 |
| 선택 기능 모듈 다운로드 실패가 정상 실적까지 숨김 | 공시 실적은 계속 표시, 해당 기능에 복구 안내와 새로고침 제공 |
| 미국 상세에서 한국 전체 종목 자료를 다운로드 | 불필요한 스크리너·회사 맥락 요청 제거 |
| 아이디어 후보마다 산업 관계를 반복 계산 | 먼저 순위를 계산하고 표시할 후보만 산업 맥락 계산·재사용 |
| 전체 스크리너 파일 다운로드가 약 11초 소요 | 이미 공개된 GitHub 저장 파일을 직접 읽도록 정적 자료 연결; 2.5초 실패 후 기존 API 복구 |
| 홈 캐시에서 먼저 보여줄 때 한국 주가의 원 단위가 빠짐 | 한국 거래소 티커의 캐시 시세에 KRW 단위 보완 |
| 부분 히트맵 수집이 반복되어 서버를 계속 사용 | 완성 캐시 공유, 실패 간격, 단일 수집 작업과 동시 요청 상한 적용 |

## 공시 기반 투자 검토 기능

1. 최근 8개 독립 분기 매출·영업이익·전년 동기 비교와 TTM. Q4는 연간에서 3분기 누적을 뺀 값이며 원문·계산법을 표시한다. 누락·통화·재무제표 기준이 다르면 계산하지 않는다.
2. 사용자가 마지막으로 확인한 공시와 새 기간·같은 기간 정정을 비교한다. 확인 완료는 명시적으로 저장하며 과거 접수번호가 최신 확인 기록을 덮지 않는다.
3. 질문 비교 결과에서 지원하는 투자 조건을 저장하고 새 공시로 재확인한다. 이전 값·비교회사·근거를 보존한다. 자료가 없거나 기준이 다르면 확인 불가로 표시한다. LLM 전망이나 매수 추천은 제공하지 않는다.

## 검증과 측정 원칙

- 최종 프런트엔드: Node 133개 테스트, AIT 계약 검사, 빌드, 17개 직접 진입 경로 검사 통과.
- 새 투자 검토 흐름은 320/390/430px 브라우저에서 확인했다. 지연 공시·503·재시도, 정정/새 기간, 비교회사 조건 저장, 선택 모듈 실패 복구를 포함한다.
- 섹터 집계·새 시세 우선·빈 응답 보존·시장 전환·구성 종목 이동·초기 요청 지연은 자동 테스트와 모바일 브라우저로 검증했다.
- 백엔드 최종 관련 회귀 40개와 번들 검사 통과. 수집 중 부분 결과가 실제 캐시에 노출되면서 관측시각을 유지하는 회귀를 포함한다.
- 같은 스크리너 입력의 아이디어 순수 계산은 **6505ms → 186ms**. 전체 결과의 깊은 동등성 및 별도 30개 입력 비교로 순위·내용 유지 확인. 이 수치는 네트워크나 전체 페이지 로딩 시간이 아니다.
- 전체 화면 측정은 운영 사이트에서 390×844px, 화면마다 새 브라우저 컨텍스트로 차례로 실행한다. DOM 준비와 첫 주요 콘텐츠 도착, API/CDN 응답, 남은 로딩, 가로 넘침, JavaScript 오류를 기록한다.
- 전후 각 1회 측정으로 서버가 가동 중인 상태의 표본이다. p95나 모든 사용자·모바일 통신망의 보장값이 아니다. API별 완료 시간은 최초 콘텐츠 시간과 다르다.

## 남는 제약

- Render 무료 서버 재기동과 외부 시세 제공처 지연은 여전히 발생할 수 있다. 지연 영역은 상태를 표시하고 날짜가 있는 기존 자료를 유지한다. 최신 자료를 확인하지 못한 경우를 새 자료로 표시하지 않는다.
- 기존 서버 CPU 상한 0.15와 지속 사용이 관측되었고, 불완전 히트맵의 반복 수집을 수정했다. 이것만으로 모든 지연의 단일 원인이라고 단정하거나 지속 CPU 개선을 보장하지 않는다.
- 정적 자료는 이미 공개된 GitHub main 파일을 직접 읽는다. 두 경로의 2504종목·기준일·갱신시각 일치, CORS=*를 확인했다. GitHub edge 캐시 최대 300초로 저장소 반영 후 최대 약 5분 지연 가능성이 있다. 기존 원자료 시각은 그대로 보인다.
- 서버 재시작 직후 시드의 미국 9개 종목/3개 섹터에서 수집 도중 미국 31개 종목/11개 섹터로 표시가 확대된 것을 실제 API에서 확인했다. 이미 진행된 캐시의 337ms 응답을 콜드 수집 전체 소요 시간으로 해석하지 않는다.
- 이번 검증은 웹 운영 및 반응형 브라우저 검증이다. 실제 Android/iOS Apps in Toss 출시 검증을 대신하지 않는다.

### 실제 사용자 흐름

- 최종 웹 배포에서 한국/미국 섹터 → 삼성전자 상세 → 8분기/TTM → 공시 확인 저장 → 하이닉스 질문 비교 → 조건 저장 → 페이지 재방문 → 코스피 실제 차트 → 미국 상세를 검증했다.
- 최종 섹터 진입 후 집계 표시 1884ms, 추가 전체 히트맵 요청 1회. 앞선 표본은 877ms였다. 초기 홈 섹터 요청 0회도 확인했다.
- 최종 성공 흐름에서는 시세/분기 재시도 없이 완료했고 오류·가로 넘침이 없었다. 별도 앞선 시도에서는 분기 요청 지연이 발생했다. 이를 숨기지 않으며 재시도/기존 자료 보존 UX를 별도로 검증했다.
- 별도 홈 완료 확인에서는 요청한 기본 영역이 1172ms에 로딩을 끝냈다. 빈 관심목록 때문에 숨겨진 뉴스 영역의 초기 placeholder는 진행 중 요청이 아니다. 측정 스크립트도 hidden 영역을 제외하도록 보완했다. 화면에 가까워져야 요청하는 섹터 영역은 이 완료 기준에서 제외한다.
