## 실제로 확인하고 수정한 문제

- 보이는 수치/상태/축약 설명이 버튼의 음성 조작용 이름에 없었다. 홈 변화·선정·히트맵, 상세 관심 버튼, 수출 모멘텀 행의 이름/설명을 연결했다. 비동기 선정 상태도 현재 표시 내용과 일치한다.
- 수출/메모리/밸류에이션 탭의 방향키 조작이 없었고, 메모리 선택을 Enter로 바꾸면 rerender 뒤 초점이 사라졌다. 수동 키보드 선택과 tab/tabpanel 연결, 선택 후 초점 복원을 추가했다. 구현 중 같은 선택을 다시 누른 뒤 복원 상태가 남는 경로도 찾아 회귀 검사로 보호했다.
- 실제 mobile 393×851 axe 4.13 검사에서 기존 14개 화면의 대비 위반 260개, 추가 관심/밸류에이션/히트맵 6상태의 28개를 확인했다. 이는 화면/펼침 상태 간 중복 노드가 포함된 수이며 고유 버그 수가 아니다. 전경 글자색만 조정했고, 전체 desktop 검사에서 추가로 나온 데이터 안내 버튼/메모리 날짜의 대비도 수정했다.
- 홈 선정 `returnPct:null`이 0.00%로, 비교 PER `null`/빈 문자열이 0배로 표시됐다. 같은 PER을 전체 지표에서는 결측으로 보여 비교 화면과도 달랐다. 기존 `finiteNumber`를 재사용해 결측/비정상 값과 실제 0을 구분하며, 결측 비교 막대도 표시하지 않는다. 제공된 실제 0과 숫자 문자열 0은 유지한다.

## 보존하는 제한과 실패 분석

기존 Toss 심사 반려 대응인 핀치 차단은 유지한다. `meta-viewport`만 명시적인 규칙 예외다. core 4.13의 기본 비활성 실험 이름 규칙은 직접 DOM→accessible-name 관계 검사로 보완한다. contrast/ARIA 규칙이나 화면 영역을 제외하지 않는다. `incomplete`는 별도 JSON 증거로 남기며, 자동 통과가 접근성 인증이나 실기기 VoiceOver/TalkBack 검증을 대신하지 않는다.

axe의 blank 결과 수집 페이지에는 origin이 없어 localStorage를 사용할 수 없다. 테스트 seed를 실제 HTTP/HTTPS 앱 페이지에만 적용하고, 앱과 열린 페이지의 치명적 JS 오류 감시는 유지했다. 실제 데이터를 fixture로 대체하는 회귀 검사와 실제 API 진단을 분리한다.

CI는 기존 reusable Playwright matrix에서 새 파일도 자동 실행하고 axe JSON/HTML/screenshot/실패 trace·video를 보관한다. 모든 main QA가 성공한 정확한 SHA만 기존 Render 브랜치로 promotion한다. tester-army/e2e와 OpenAI/외부 LLM/API 키는 사용하지 않았고, 새 API 사용 비용·유료 서비스·Render 플랜 변경은 없다.
