## 보존하는 계약

- 세 저장소는 기존 Toss 익명 계정별 기기 저장소와 초기화에 등록한다. 성공은 저장 확인 이후에 표시하며 대기 중 초기화/계정 전환을 보호한다. 손상 기록은 오류를 표시하고 덮어쓰지 않는다.
- 재점검 완료는 직접 확인한 기록이며 원래 질문/공시를 바꾸지 않는다. 사용자가 본 자료의 변경을 감지하고 새로운 질문/공시를 완료 기록으로 가리지 않는다.
- 비교 세트를 실행해도 관심종목은 바뀌지 않는다. 다른 종목 조회가 실패하면 이전 종목 그래프를 새 선택 아래에 표시하지 않는다. 같은 종목의 기간 조회 실패는 기존 결과 보존 정책을 유지한다.
- 뉴스 근거는 종목당 20개/전체 100개, 메모 300자. 같은 종목/HTTPS URL은 중복하지 않으며 날짜만 제공된 기사를 임의 시각으로 바꾸지 않는다.
- 개인 메모·세트 이름·저장 기록은 공유 URL과 분석 이벤트에 포함하지 않는다. 기존 검색 API에는 실행한 조건/종목만 전달한다. 개인정보 안내와 초기화 문구를 갱신했다.

## 검증 기록

깨끗한 기준 커밋의 Node 753개를 먼저 통과했다. 새 저장소/상태/UI의 실패 회귀를 먼저 관찰하고 구현했다. 독립 검토에서 실제 section 호스트의 재점검 갱신, 미표시 공시 완료, 실패 조회의 완료 해제, 지연 저장의 초점, 초기화 뒤 비교 선택 복원, 다른 종목 조회 실패의 이전 결과 혼동을 확인하고 보완했다.

첫 새 기능 브라우저 검사 40회 중 36회 통과/4회 실패는 기사 제목에 두 회사명이 포함되어 Watch 버튼 선택자가 두 개를 가리킨 테스트 문제였다. 버튼의 회사명으로 선택 범위를 정확히 고쳤다. 강화한 Watch→근거 이동 검사에서는 실제 모바일 화면 밖으로 밀리는 문제를 재현했다. 새 펼침 화면 axe 검사는 재점검 메뉴 글자 대비 한 곳을 재현했다. 해당 회귀를 유지하며 수정 후 다시 검증한다.
