# 수출 모멘텀 1차 기반

## 목적
API 키가 아직 없는 상태에서도 차트뷰 토스의 수출 데이터 화면과 데이터 계약을 먼저 고정한다. 첫 버전은 공식 발표 수치를 정규화한 정적 JSON을 읽으며, 관세청 API 연결 시 데이터 공급부만 교체한다.

## 현재 데이터 흐름
1. 공식 관세청 1~10일, 1~20일, 월 전체 잠정치 확인
2. 산업통상부 월간 수출입동향에서 품목·지역 설명 보강
3. `public/data/export-momentum.json`에 동일 스키마로 저장
4. `#exports` 화면이 정적 스냅샷을 읽어 렌더링

현재 스냅샷은 2026년 9월 자료다. 실제 앱 화면에는 공식 잠정치와 스냅샷 방식임을 명시한다.

## 데이터 계약
- summary: 총수출, 수입, 무역수지, 전년비, 누적 수출
- checkpoints: 1~10일 / 1~20일 / 월 전체 누적치
- items: 주요 품목 수출액(제공될 때만), 전년비, 공식 설명
- regions: 주요 지역 전년비 및 제공 가능한 수출액
- sources: 사용한 공식 원문 URL

누락된 금액은 `null`로 유지한다. 추정값을 만들지 않는다.

## 다음 단계: 관세청 API
관세청 ServiceKey가 준비되면 아래 순서로 확장한다.
1. shared backend에 `/api/export-momentum` 추가
2. HS 코드별 / 국가별 원자료 수집 및 서버 캐시
3. 3개월·6개월 추세와 전월/전년 비교 계산
4. 프론트 데이터 공급부를 정적 JSON에서 backend endpoint로 교체
5. 정적 JSON은 장애 시 fallback 또는 회귀 fixture로 유지

## 성능 원칙
- Home 첫 화면 요청에는 수출 데이터를 추가하지 않는다.
- 사용자가 `#exports`에 들어갈 때만 lazy-load한다.
- 기존 시세 polling, heatmap, DART 흐름과 완전히 분리한다.
- API 연결 후에도 서버에서 정규화/캐시하고 클라이언트가 관세청을 직접 호출하지 않는다.

## 범위
이번 1차 버전은 통계 조회 화면이다. 수출 증가율을 종목 매수/매도 신호로 표현하지 않는다. HS 코드→업종→상장사 연결은 데이터 품질과 Apps in Toss 노출 범위를 별도 검토한 뒤 추가한다.
