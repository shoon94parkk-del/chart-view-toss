## Home / feedback / routing implications

- **Do not prioritize a new 07/12/16 briefing subsystem yet.** Current Home already has a source-based market brief, previous-visit price evidence, public receipt changes, research continuation and three interest news items (`F/src/main.js:645–649,709–715`). A small “읽기/근거 펼치기” presentation can reuse these, but a true timed edition requires an immutable published edition/content/timestamp and a timezone schedule. A clock label on refreshed live data is not an edition. Do not add initial Home provider work merely for parity.
- The general feature route list is `F/src/routes.js:3`; detail and stock-news direct routes are `:15–21`. Research and filing review are detail sections rather than separate TODO/research routes. Existing explicit review acknowledgement should not be mislabeled a generic task system.
- Feedback/review are already partly covered: `F/src/reviewPrompt.js:6–27,33–47` gates the optional native review prompt and opens it only on a tap; it cannot verify review submission. `F/src/main.js:1666,1747` shows plain-text contact email on info/more. A copy/contact action is a small additional idea; a dedicated feedback inbox would need submission/storage/operations infrastructure. `F/src/researchCard.js:226` already offers optional native review after a successful research save.
- Preserve PICK/LAB/strategy/mathematics/source API contracts. None of these ideas needs trading ratings, copied Moneytoring copy/content, or a change to selection calculations. Prefer the first three before larger historical-data work.
