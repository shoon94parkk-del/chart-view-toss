The response carries row `observedAt`, `status`, units and change basis (`main.py:1843–1883`), collection `generatedAt`, source, freshness/error counts, and newest/oldest source-observation dates (`main.py:2099–2128`).

Repository search found only an external Investing.com “경제 캘린더” tool link (`static/js/investment_tools_v22.js:7`).

A visible FRED series link is not proof that each row was fetched directly from FRED.

## Afterns-style earnings events versus existing consensus

- **Existing:** corporate EPS/revenue estimates, analyst counts, revision counts, fiscal period `endDate`, and dated accumulated estimate snapshots. The fetch explicitly requests Yahoo modules `price,earningsTrend` (`consensus_service.py:136–154`). `endDate` is a fiscal period end, not a confirmed earnings announcement date. `yearAgoEps` is a prior-year comparative embedded in Yahoo's estimate period, not an event-aligned actual EPS result (`consensus_service.py:56–93`).
- **Absent in audited source/data contracts:** earnings event calendar; confirmed-versus-estimated announcement dates; BMO/AMC/exchange-timezone announcement timing; source-published earnings actuals; actual/consensus matched by same period and adjusted/non-GAAP/GAAP basis; EPS/revenue beat/miss or surprise calculation. No earnings-history/calendar module is fetched, and no earnings-event API or checked-in event dataset was found. DART Guru does hold reported Korean quarterly **Basic EPS** with original filing/period evidence (`guru_extensions.py:22–45`), but it is used for prior-year fundamental growth checks (`:159–175`), not paired with Yahoo consensus. It must not be joined to adjusted analyst estimates without explicit comparability proof.
- **Useful price building block:** `GET /api/compare` supports validated custom date ranges and multiple tickers, with adjusted-close fallback, exchange timezone and observation count (`main.py:990–1043`, `market_service.py:209–251`). This could support a future event-study implementation after event/baseline definitions and alignment rules are added.
- **Absent event analytics:** a dated announcement/session pipeline defining close before event versus regular close after event, event-aligned drift windows, SPY excess returns, event volatility or historical earnings cohorts/sample denominators. Generic compare returns are each symbol's first-to-last available observation rather than matched event sessions (`main.py:1035–1042`). Its `observations` is chart-point count, not number of earnings events. Existing guru `relativeStrengthPercentile` is a 252-session market-universe rank (`guru_extensions.py:120`), not SPY event excess performance. Generic chart fetching sets `includePrePost=false` (`market_service.py:178–190`), but this does **not** prevent Afterns-style regular-close-to-regular-close reactions; those regular adjusted closes are a reusable input once event timing and session alignment exist. Separate after-hours-bar analytics would need another data contract, but are not a prerequisite for those close-to-close reactions.
- A faithful first version therefore needs a new, explicit earnings-event dataset and compatible actual/consensus source, announcement-time confidence, immutable pre-event estimate snapshot, event-to-session alignment and separate event sample/coverage counts. Existing consensus and price comparison can be reused as inputs only where their provenance and semantics fit. This is separate from the missing economic calendar/CPI/PPI work above.

## Financial/source-date/methodology availability

- `GET /api/financial-history` returns annual revenue/operating profit, latest cumulative interim comparison and quality accounts. It prefers CFS, labels OFS fallback and preserves basis/currency consistency. Annual/interim receipts link to the original DART filing; quality accounts expose source account IDs/names/statements/period labels/receipt numbers (`dart_financial_service.py:82–123,126–162,230–294,380–386`). The revenue/profit history itself has receipt links and year/quarter labels rather than the richer account metadata used by quality.
- `GET /api/financial-quarters` exposes eight quarters, YoY comparisons, margins and TTM only from four compatible available quarters. Each quarter has `sourceUrls`, basis/currency and explicit method (`reported_three_months`, `reported_q1`, `cumulative_difference`, `annual_minus_q3`); unavailable observations stay null (`dart_quarter_service.py:26–66,178–182`). Cold static results can be returned while a background refresh runs (`dart_quarter_service.py:159–176`).
- `GET /api/business-report` has report year/name, authoritative `rceptDate`, receipt, original URL, source/mode, segment revenue basis/unit, confidence and reconciliation metadata (`dart_business_service.py:1331–1351,1361–1374`). Korean-only; overseas DART identity is rejected.
- The three checked-in detail caches cover **14 major Korean companies**, not the whole market: 000270, 000660, 005380, 005490, 005930, 006400, 033500, 035420, 035720, 042660, 066570, 068270, 207940, 373220. All 14 are available in saved data. Financial history root generatedAt is **2026-10-10T10:09:08+09:00**; quarterly cache ends **2026 Q2** for all 14; business root updated is **2026-10-16T08:45:39+09:00**, zero reported failures. These are source-cache observations, not live service checks.
- **Verification-date gap:** all 14 rows in all three static caches omit `checkedAt`. This is intentional source behavior to commit only data changes: financial generator strips it (`scripts/generate_dart_financial_history.py:39–52`), quarterly generator removes it and has no root build timestamp (`scripts/generate_dart_financial_quarters.py:19–24`), business generator removes volatile dates and only advances root `updated` when content changes (`scripts/generate_dart_business_context.py:43–49,127–138`). Thus a recent workflow check cannot be inferred from unchanged cache `generatedAt`, nor can the quarter cache report a latest verified timestamp. Original filing links/periods remain available.
- Unlike macro, detail requests may collect/revalidate official DART data in cold/background paths (`dart_financial_service.py:350–376`, `dart_quarter_service.py:170–172`); this audit did not call those routes. Existing scheduled DART workflow runs daily 21:30 UTC and generates business, financial and quarters (`.github/workflows/update-dart-business-context.yml:4–5,38–45,68–71`).

## Concrete gaps to carry into product planning

1. Additive data work is required for CPI/PPI, scheduled release calendar/timezones, economic forecasts, actual-vs-consensus surprises and associated source/publication/revision dates; current macro data cannot supply them.
2. Source observation date, source publication time, successful verification time and cache build time are only partially modeled across domains. Preserve the distinctions: macro `current` is success-based; financial static `checkedAt` is stripped; exports lack official publication time; corporate consensus `asOf` is collection time.
3. Forecast labels need domain precision: corporate analyst consensus, descriptive macro regime and export completion-ratio projection are three different existing contracts.
4. Structured common linkage among macro series, sector/theme taxonomy, companies, export HS exposure and related news is absent. Available building blocks are official industry/main-product text, keyword relevance, original news links and narrow explicit counterparty evidence.
5. Coverage limits must remain visible: financial detail static 14 Korean issuers; corporate consensus 56 symbols; macro PCE only six observations; memory public-history depth is runtime-dependent; HBM independent export and price series unavailable. No missing value should be fabricated to fill these gaps.
6. Afterns-style earnings work requires event dates/timing and actual/consensus comparability before surprises or post-announcement statistics. Generic chart point count, analyst count and earnings-event sample count are distinct denominators.
