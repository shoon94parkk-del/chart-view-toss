가상의 화면 문구 예시는 `최근 발표 → 해당 자료의 기준월/확정 여부 → 실제 값과 이전 값 → 원문·기존 상세 보기` 순서다. 값과 날짜는 실제 응답이 있을 때만 채운다. 시장 예상치가 없는 자료에는 예상 대비 차이를 표시하지 않는다. 예상치가 없다는 이유로 전월 수치를 시장 예상치처럼 쓰지 않는다.

**그대로 도입하지 않을 부분**

- `12회 중 5회 상승`은 과거 관측 비율이다. 미래 상승 확률·매수 신호로 표시하지 않는다. 실적과 주가가 반대로 움직인 횟수만으로 가이던스가 원인이라고 확정하지 않는다. 이 조사에서는 AFTERNS 수치나 인용문의 정확성을 재계산·원문 대조하지 않았다.
- 주가 반응을 제공한다면 발표 전 마지막 종가와 발표를 반영하는 첫 정규장 종가의 기준, 장전/장후·휴장일·기업행동·누락 처리부터 정의해야 한다. 기존 일반 수익률 비교의 차트 포인트 수는 실적 발표 횟수가 아니다.
- 모바일에서 데스크톱의 여러 컬럼·12분기 타임라인·상시 대화/투표 패널을 그대로 옮기지 않는다. 직접 본 390px 화면에서 하단 내비게이션과 Talk 패널이 함께 공간을 차지했다. 차트뷰는 기존 하단 내비게이션을 유지하고 핵심 요약과 상세 이동을 우선한다.
- 자동 AI 코멘트·커뮤니티·투표·보상·강제 알림·리뷰 요청을 이번 벤치마크의 필수 기능으로 제안하지 않는다. 검증된 원문과 기존 연구 흐름을 먼저 활용한다.
- AFTERNS에 SEC/Yahoo 출처 표기가 있다고 차트뷰가 해당 사이트 데이터·요약·인용을 복제할 권리를 확인한 것은 아니다. 공개 열람·robots 허용도 재배포 허가와 별개다. 구현 시 차트뷰가 직접 이용 가능한 원천의 조건을 확인한다.

**공식 문서에서 확인한 유용한 점과 미확인 사항**

[About](https://afterns.com/en/about)는 발표 반응을 발표 전 마지막 종가부터 발표 후 첫 종가까지로 정의한다. [컨센서스 가이드](https://afterns.com/en/guide/earnings-consensus)는 조정 actual EPS와 같은 기준의 consensus를 비교한다고 설명한다. [NVDA 화면](https://afterns.com/en/stock/NVDA)은 표본 수와 `never missed` 등의 빈 경우를 드러낸다. 이 세 가지는 시각적 디자인보다 먼저 참고할 정보 설계다.

다만 일정 화면은 ET와 추정 날짜를 제공하는 반면 [구독 가이드](https://afterns.com/en/guide/earnings-calendar)는 확정 일정·현지 시각을 설명한다. 익명 구독 범위에 관한 About/Calendar 문구도 일부 다르다. 화면 조회와 구독 피드의 범위 차이일 수 있으며 실제 구독·알림을 시험하지 않았다. 이를 정상 동기화가 입증된 기능으로 표시하지 않는다. 같은 이유로 사이트의 갱신 속도 설명은 측정한 SLA가 아니다.

**검증·산출물·남은 범위**

- REA의 canonical 접근성/관찰 JSON, PNG, SHA256과 Evidence ID를 [근거 목록](EVIDENCE.md)과 [기계 판독 인덱스](evidence-index.json)에 보관했다. 공개 문서의 원문·발췌·수집 시각은 [공식 문서 조사](official-sources/research-summary.md)에 있다.
- 브라우저 크기 비교는 Chromium의 390px 및 1440px 관찰이다. 실제 iPhone/WebKit, Android 기기, 토스 Sandbox, 로그인 후 화면, 구독 피드, 알림, 데이터 정확성·라이선스·전체 접근성·성능 전후 비교는 검증하지 않았다.
- 제품 수정이 없어 단위/E2E/AIT 빌드·재배포를 수행하지 않았다. PR134의 기존 GitHub 성공 체크와 이번 조사 검증은 구분했다. 관련 작업 폴더의 추적 파일 변경이 없음을 확인했다. REA·연구 도구와 문서/스크린샷만 별도 연구 디렉터리에 생성했다.
- PICK 선정·기록·점수·상태·API·노출 조건·사후 성과와 LAB 핵심 판단, 기존 계산식·전략·면책 문구는 전부 무변경이다. 향후 공통 UI를 수정하게 되면 보호 영역의 출력·동작 동일성을 별도 회귀 검증해야 한다.
- 신규 분석 SDK·이벤트·리뷰 API는 이번 조사에서 확인하거나 연동하지 않았다. 제안 기능의 측정은 실제 상세 로드 완료와 저장 완료를 구분하는 기존 이벤트 구조를 재사용하되, 공식 SDK/콘솔 규격 검증 후 결정한다. 검색어·개인 메모·관심종목 목록을 외부 분석으로 전송할 이유는 없다.
- Apps in Toss 추천/부스팅 선정이나 특정 투자 서비스 허용 여부는 이 벤치마크로 판단할 수 없다. 사용자 만족·재방문 향상은 검증할 제품 가설이며 선정 보장이 아니다.
