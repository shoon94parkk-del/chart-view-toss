# 기업 공부 — 구현·운영·검증 기록

사용자 요청: 기존 Chart View Toss 안에서 매일 25분 기업 공부를 하고, 지식·퀴즈·투자 판단을 1년 이상 축적하는 개인 학습 시스템. 새 기능으로 분류했다. 토스 프론트엔드는 이 저장소, 공용 FastAPI는 `shoon94parkk-del/chart_View`에 추가했다. 별도 웹 UI와 기존 기기 내 조사 카드는 유지한다.

## 화면과 사용 순서

홈 또는 분석 메뉴의 **기업 공부**에서 시작한다. 기존 네 개 하단 탭과 네이티브 뒤로가기를 유지한다.

1. 새 학습 계정을 만들고 처음 한 번 나오는 복구키를 안전하게 보관한다. 다른 브라우저·기기는 이 키로 같은 계정을 연결한다.
2. 대시보드에서 오늘/다음 공부, 실제 학습 일수·연속 일수·기업 수·객관식 누적/평균·자기 이해도·복습 대상을 확인한다.
3. 25분 자료와 공식 출처를 읽고 노트를 저장한다. 초안은 비어 있어도 저장할 수 있다. 성장 이유·가장 큰 위험·확인 지표 세 가지를 직접 적어야 공부 완료를 저장할 수 있다.
4. 공부 완료 후 객관식 답과 투자 판단 근거, 증거·논리·지표 자기평가를 제출한다. 서버가 실제 답안을 채점하며 완료 버튼만으로 퀴즈를 제출하지 않는다.
5. 오답·취약 개념과 예정일을 따라 복습한다. 과거 노트를 수정해도 개정·답안·점수는 남는다. 수정한 노트는 해당 개정으로 재평가하기 전 공부 완료 상태다.
6. 과거 투자 가정을 실제 사업 결과·원문·기준일과 비교해 지지/반박/미결론을 기록한다. 가격 관측은 참고이며 투자 논리의 정답 판정에 사용하지 않는다.

산업별 객관식 평균·복습 수·자기 이해도·표본 수, 실제 제출 주간 점수 그래프와 주·월 통계를 제공한다. 실적 근거 검증의 지지/반박/미결론 수는 사용자 기록으로 표시하고 점수와 분리한다. 한국 날짜와 실제 완료/제출 시각을 사용하므로 미래 수업을 미리 공부해도 미래 날짜의 활동을 만들지 않는다. 빈 값과 실제 0을 구분한다.

종목 상세·관심·스크리너·PICK/히스토리의 **기업 공부 · 학습 이력과 후보**를 펼치면 현재 기업들의 마지막 공부·자기 이해도·현재 개정 퀴즈와 기록을 연결한다. 기본 종목 화면 로딩 중에는 학습 API를 호출하지 않는다. 미학습은 학습 후보이며 새로운 매수 추천 등급이 아니다. PICK의 날짜/키/공개 선정 근거와 스크리너의 표시 근거를 허용된 범위에서 새 학습 출처로 보존한다.

## 커리큘럼과 ChatGPT 가져오기

2026-11-02 월요일부터 화장품 → K-푸드 → 조선·LNG → 방산 → 원전 → 전력기기의 6주, 요청한 18개 기업을 제공한다. 월~수 개별 기업, 목 가치사슬, 금 비교, 토 거시 시나리오, 일 복습이다. 각 수업은 25분이며 고정 재무 수치를 만들어 넣지 않는다. 최신 공시의 기간·통화·연결/별도·원문을 직접 확인한다.

설정의 커리큘럼 JSON에서 산업·기업 순서와 주차를 편집하고 마지막 주를 복사해 늘릴 수 있다. 월요일 시작, 주당 세 기업과 고유 식별자를 검증한다. 저장한 과거 수업과 채점 문항은 변경하지 않는다. 카탈로그 밖 종목도 기존 종목 화면에서 직접 공부할 수 있으며 확인되지 않은 사업 사실은 생성하지 않는다.

ChatGPT 대화와 21:30 예약 작업을 자동으로 읽는 연동은 없다. 설정의 예시 형식에 맞춘 `chartview-learning-result` JSON을 붙여 넣거나 파일을 선택하고, 미리 본 뒤 직접 확인해 가져온다. 외부 점수는 출처를 표시하고 자체 퀴즈 완료를 만들지 않는다. `chartview-learning-backup` JSON은 전체 기록을 내보내고 원자적으로 합쳐 복구한다. 복구 파일의 다른 내용/같은 ID 충돌은 기존 데이터를 보존한 채 거절한다.

## 저장과 인증

운영 저장소는 공용 백엔드의 PostgreSQL이다. `LEARNING_DATABASE_URL`을 우선 사용하고, 없으면 `DATABASE_URL`을 사용한다. 상세 설정은 [백엔드 운영 안내](https://github.com/shoon94parkk-del/chart_View/blob/main/docs/INVESTMENT_LEARNING.md)에 있다. 새 프론트엔드용 비밀 환경변수는 없다.

서버는 복구키·세션 토큰의 해시만 저장한다. 세션은 30일 후 만료되고 로그아웃하면 폐기된다. 만료는 계정/학습 데이터 만료가 아니며 복구키로 다시 연결할 수 있다. 기기에는 계정별 세션 토큰만 보관한다. 복구키를 잃으면 이메일로 복구할 수 없다. 다른 탭에서 계정을 바꾸면 이전 계정의 초안을 새 계정으로 보내지 않는다.

개인 기록은 서버 문서와 수정 이력에 보존한다. 트랜잭션·버전 충돌·작은 멱등성 영수증으로 동시 수정과 불확실한 저장 재시도를 처리한다. 저장 응답을 잃은 새 기록은 원래 요청을 먼저 확인해 같은 기록 ID로 수정하므로 중복 생성하지 않는다. 같은 계정의 초안은 화면 왕복과 인증 만료/복구에서 유지한다. 확정하지 않은 저장을 성공으로 표시하지 않는다.

기기 데이터 초기화는 기기 로그인과 기존 기기 기록을 지운다. 서버 학습 데이터는 남는다. 서버 학습 계정 영구 삭제는 별도 명시적 확인이 필요하다. JSON 백업에는 인증 정보와 비공개 정답 정의가 없다. 이전 평가를 가져오면 가져온 출처를 유지하고 새 자체 평가 제출로 간주하지 않는다. 운영 재해 복구에는 DB 제공자의 백업도 사용해야 한다.

계정 문서는 128MiB, 일반 명령은 4MiB, 가져오기는 160MiB로 제한한다. 보통의 매일 노트 1년을 지원하도록 여유를 두었지만 모든 필드를 최대 길이로 매일 여러 번 저장하는 사용량까지 보장하지 않는다. 과거 이력을 자동 삭제하지 않으며 초과 요청은 원자적으로 거절한다. 매우 큰 문서에는 추후 분리 저장/스트리밍이 필요하다.

## 현재 운영 DB 상태

확인한 Render 워크스페이스는 **Chart View**다. 기존 `chart-view-profile-sync` 무료 PostgreSQL은 **2026-10-21 사용 기한 만료로 정지**되어 있다. 이번 달 용량 초과가 아니며, 다음 달이 되어도 자동 복구되지 않는다. 유료 자원은 승인받지 않아 생성하지 않았다.

후속 작업에서 사용자가 지정한 **Neon 무료 PostgreSQL 18의 production**을 연결했다. 기존 Render 화면/API는 그대로 유지하며 백엔드의 `LEARNING_DATABASE_URL`만 설정했다. 현재 운영 학습 저장과 다른 브라우저 복구가 가능하다. 미설정·연결 실패 시 서버가 쓰기를 거절하는 원칙은 유지하며, 테스트용 로컬 PostgreSQL/SQLite를 운영 저장소로 사용하지 않는다. [Neon 설정과 운영 검증](NEON_SETUP.md).

## 검증 근거

- 프론트엔드 기존 기준 894개 → 최종 Node 929개 통과. 새 학습 계약 31개와 라우트/기기 인증 저장 회귀를 포함한다.
- 백엔드 기존 기준 1,207개 → 최종 Python 1,327개 및 43 subtest 통과. 학습 계약 120개는 실제 PostgreSQL과 로컬 SQLite를 포함한다. 기존 웹 Node 52개와 생성 번들 정합성도 통과했다.
- 독립 검토에서 잘못된 커리큘럼 저장, 큰 revision의 메모리 할당, 인증 전 큰 본문 소비, 다른 탭의 계정 변경, 초안 왕복, 응답을 잃은 저장 중복과 인증 만료 초안 손실을 재현하고 회귀를 추가해 수정했다.
- `tests/learning_postgres_qa.mjs`: 실제 FastAPI·PostgreSQL·프로덕션 빌드에 대해 14개 검사 통과. 새 백엔드 프로세스와 PostgreSQL 재시작 전후 문서 해시·버전·학습 ID, 1개 공부/3개 개정/2개 답안/1개 복습/1개 근거 검증/6개 요청 영수증이 같았다. 독립 복구 로그인·로그아웃 401·계정 격리·백업 무비밀·0 보존, 320px와 iPhone WebKit 화면을 검증했다. 두 검사용 계정은 삭제하고 DB 제거도 확인했다.
- 새 브라우저 시나리오는 10개 × 4기기다. 별도 병렬 실행은 39통과/1 iPhone 시간 초과였고, 실패 trace와 실행 부하를 보존했다. 필수 전체 `qa:prepush`에서는 새 학습 40개 모두 통과했고, 전체 1,314개 통과/기존 PICK 준비 조건 2개 실패를 기록했다. 새 학습 연결 footer가 66px을 추가해 원래 복귀 위치가 임시 화면에서도 도달 가능해진 것이 원인이었다. 실제 복원 엔진은 그대로였으며, 화면 header/nav 안에서 클릭 대상을 유지하며 더 아래 위치를 저장하도록 준비 절차를 보강했다. 도달 불가 조건·1px 복원·사용자 취소 assertion은 유지했고 네 환경 8개 대상 검사가 모두 통과했다. 최종 전체 CI 결과는 게시 기록에서 확정한다. 시간 제한·판정 기준·재시도 기준을 완화하지 않았다.
- 기존 모바일 연속성 QA는 320/390/430px의 메뉴·정체성·밀도·출처·터치 영역에서 통과했다. 승인된 기존 audit-plan QA도 320/390/1440px 모두 통과했다. `npm run build:ait`가 `chartview.ait`를 생성했다. 이는 빌드 검증이며 토스 앱 공개 배포가 아니다.
- 첫 백엔드 PR CI는 Ubuntu26.04/Playwright1.55 비호환으로 브라우저 설치 전에 실패했다. 검증된 Playwright와 테스트는 유지하고 필요한 두 저장소의 브라우저 CI를 Ubuntu24.04로 고정했다. 이후 실제 새 head의 검사를 별도로 확인한다.

## 게시 기록

백엔드 [chart_View #169](https://github.com/shoon94parkk-del/chart_View/pull/169)와 runner 후속 [#170](https://github.com/shoon94parkk-del/chart_View/pull/170)이 통합됐다. 최종 main `c1a1fcd70fe03e525abd6100ae06af1680f69d8a`는 Render `dep-dbjl8dlg1s2s73834l1g`에 배포됐다. 실제 `/health` revision 일치, 18개 기업/6주/2026-11-02 시작일, 미인증 401/no-store, 저장소 미설정·계정 생성 503, 기존 Home 요약 200을 확인했다. main App Regression과 Production Mobile Verification도 통과했다.

프론트엔드 [#151](https://github.com/shoon94parkk-del/chart-view-toss/pull/151)은 Node 929개·브라우저 1,316개와 필수 CI를 통과하고 main `8ea2f5c94918b876748dae99c40608df2161d96e`으로 통합됐다. 이후 main의 독립 배포 전 검사에서 기존 PICK 위치 복원 검사가 첫 시도 66px 오차/재시도 통과를 기록했다. fail-on-flaky 정책이 정적 사이트 승격을 차단했다. 원인은 학습 연결 영역의 동적 모듈이 PICK의 마지막 위치 복원 뒤 도착해 문서 높이를 바꾼 경합이었다. 연결 영역의 작은 표시 모듈을 동기 배치하도록 수정했으며, 인증 조회와 API는 여전히 사용자가 펼친 뒤에만 실행한다. 첫 ready 레이아웃을 감시하고 선택적 모듈 전달을 보류하는 회귀 검사가 수정 전 실패/수정 후 통과했고, 네 환경의 PICK·종목 연결·Home 지연 로딩 관련 48개가 모두 통과했다. 점수·타이밍·재시도·위치 판정 기준은 완화하지 않았다. 이 후속 변경의 전체 CI와 실제 정적 자산 게시 결과는 PR 게시 기록에서 확정한다.

최초 게시 시점에는 운영 DB 미연결로 배포 후 개인 기록 보존 검사를 실행할 수 없었다. 이후 Neon 연결 후 별도의 실제 운영 검증을 수행했다. 로컬 재시작 보존 결과와 운영 검증을 구분한다. Render 웹 확인과 실제 Android/iOS Toss Sandbox·공개 출시는 별도다.

Render 재배포 `dep-dbjqkjvb9u1s73eq5jf0` 전후 문서 해시·공부 ID·버전6과1공부/3개정/2답안/1복습/1근거 검증이 정확히 일치했다. 임시 계정2개는 삭제했고 이전 인증이 거절되는 것도 확인했다.
